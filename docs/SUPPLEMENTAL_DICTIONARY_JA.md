# 同梱辞書の候補補完（Issue #132）

1.3.0の対象。mac版PR #37を参考に、SudachiDict Core 20260723から作成した索引と
Sumibi独自の中黒用辞書を導入する。初回変換やAPIのプロンプトには変更を加えない。

## 動作

「さらに変換候補を取得」の成功応答を受けた後に、LLM候補の最初の全ひらがな候補
（長音記号を含む）を読みとして完全一致検索する。文章だけ・未知の読みなら補完しない。
LLM候補の順序を保ち、既存のLLM表示枠とは別に、重複を除いて辞書から最大10件を末尾へ加える。
辞書の全体や検索結果をAPIリクエストへ追加せず、辞書検索の追加通信・トークン消費はない。
追加API要求そのものは従来どおり課金・送信同意・フルアクセスの対象。
通信失敗時を辞書だけで救済するオフライン変換ではない。

別ファイル `BuiltinCandidates.tsv` に、独自作成の `ten → ・`、`nakaguro → ・`、
`. → ・` を同梱する。全ひらがな候補の有無やSudachiDictへの中黒収録に依存しない。
入力全体の完全一致だけを対象とし、文章中のピリオドを一括置換しない。
中黒をLLMが返した場合は出所をLLMとして保持し、表示上限でも中黒用の枠を確保する。
辞書で補った場合は「辞書」と表示する。

### 記号辞書（Issue #133）

Mozcの `symbol.tsv` とローマ字対応表から生成した `MozcSymbols.tsv` を追加する。
入力全体の読みと一致する記号を検索し、LLMがひらがな候補を返さなくても補完する。
`hoshi`／`hosi`／`ほし` → ☆・★、`maru1`／`maruichi`／`まる1` → ①、
`maru2` → ②、`yajirushi` → →・←・↑・↓、`mugendai` → ∞など。
実際の変換候補表示は、従来どおり追加候補のAPI応答が成功した後に行う。
記号辞書から独立したオフライン変換や、入力途中の記号への自動置換は行わない。

記号の検索は入力全体で行い、ASCII大文字小文字を区別しない。文章中の部分一致は使わず、
互換正規化で①を1へ変える処理もしない。候補の追加順は独自中黒→Mozc記号→Sudachi同音異義語。
辞書候補の上限は3辞書の合計10件で、LLM候補と重複する文字列は追加しない。
中黒を優先し、`ten`・`nakaguro`・`.`の既存動作を維持する。
広い読み（`hoshi`など）は上限内だけを表示するので、黒星だけなら`kuroboshi`のような具体的な読みも使える。
絵文字用フォントが高くなる一部の単独記号は、表示だけを文字用字形・13ptへ調整する。
通常の候補は15pt、「LLM／辞書」は14ptの補助文字色を維持し、40ptの候補欄を広げない。
表示用の字形指定は本文へ挿入せず、辞書にある元の記号だけを挿入する。

候補の本文と出所情報は別に保持する。「原文」以外の候補は本文の下に小さな
「LLM／辞書」を表示し、VoiceOverにも出所を含める。元の候補バー高は変更しない。
候補を押したときだけ本文を置換し、注釈は挿入しない。現在候補の出所は再描画後も保持する。
選択・Undo・入力先が編集された場合の置換防止は既存処理を使う。

## データとメモリ

索引は28,912読み、約1.1 MBのUTF-8 TSV。キーボード拡張へ同梱し、
追加候補を初めて表示するときに一度だけ読み込む。
元のUTF-8バイト列と行の位置を保持し、読みの二分探索で必要な表記だけを文字列へ変換する。
各索引を独立して読み込む。一つが欠損・不正UTF-8でも他の辞書は使え、すべて読めなければLLM候補だけを表示する。

Mozc記号索引は18,581読み・約407 KB。出典・固定元データのハッシュ・再生成手順は
[Mozcの第三者表示](../ThirdParty/Mozc/README.md)に記録。辞書の読み込み方式は同じ二分探索索引を使う。

出典、加工内容、元データのハッシュ、再生成手順は
[ThirdParty/SudachiDict/README.md](../ThirdParty/SudachiDict/README.md)に記録。
同梱索引SHA-256：
`9c7d18e2183cd7f554e6d81fbf0c375e435b192fa5e112d10cc4247cd132f269`。
公式のsmall_lex／core_lex ZIP内には各CSVだけが含まれていたため、
同じ公式版のリポジトリからLICENSE・LEGALを別途取得して原文どおり同梱する。

設定の末尾から「ライセンス」画面へ遷移し、MIT全文・Sudachiの出典と著作権・
Apache-2.0全文・UniDic／NEologdの表示を含むLEGAL全文を端末内で閲覧できる。
Sumibi独自コードと中黒用独自辞書のMIT、Sudachi由来データの条件を区別する。
Mozcの出典・加工内容・著作権表示とBSD 3-Clauseを含む公式LICENSE全文も閲覧できる。
