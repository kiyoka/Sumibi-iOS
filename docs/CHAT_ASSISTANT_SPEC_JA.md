# Sumibiに相談：使い方・費用の案内（Issue #120）

状態：2026-10-05実装。2026-10-06にiPhone 17eへ上書きインストールし、利用者から正常動作の確認を得た。

関連：#12、PR #119、#120。

## 方針

「チャットで設定」を「Sumibiに相談」に変更する。使い方、現在の概算費用、任意期間の将来費用を質問でき、従来のモデル・音・振動の設定変更も利用できる。文体プリセットは通常の設定画面へ案内し、チャットから変更しない。

アプリが日数ごとの予測額を計算してLLMへ渡す方式ではない。LLMへ参照情報を渡し、質問の期間や利用量の倍率、会話の続きを読み取って見積もり・説明するようにプロンプトを調整する。タイムアウトは15秒固定。

## 参照情報

- 現在のアプリの操作ガイド。範囲変換、候補選択・Undo、記号、辞書、プリセット、利用状況、遊び心のあるキーボード、初期設定・トラブル確認を含む。
- 保存済みの変更対象4項目と共通のモデル選択肢。
- 送信直前の日時（ISO 8601、UTCオフセットを含む）、端末のタイムゾーン。
- モデル別の累積統計：集計開始日時、変換回数、設定チャット回数、入力・キャッシュ入力・出力トークン、既存料金計算によるUSDの概算費用。
- 料金判明分の小計と料金不明モデルの一覧。開始日時・料金が不明ならnullを送り、0と区別する。

毎回送信前に統計を再読込する。今回の回答自体の未確定な料金は含めない。変換原文、APIキー、実際の辞書やプリセット情報は追加で渡さない。既存の第三者AIへの送信同意を必要とし、送信情報を画面とプライバシー説明に明記する。

## プロンプト

指示・架空の回答例・操作ガイド・設定・実際の利用統計を分ける。例の数値を実際の統計として扱わせない。

- 「今後15日」「30日」「1週間」などの期間を自然言語から理解する。
- 「2倍使う」「では30日なら？」などの条件・会話の続きを理解する。
- 記録された平均ペースを基本に、LLM自身が計算する。日数・将来額をアプリで事前計算しない。
- 今後の追加費用と、現在までを含めた累計を区別する。
- 各モデルの集計期間を考慮し、根拠と前提を短く添える。
- 記録が1日未満なら不安定な参考値と説明。開始日時不明・未来・期間0・料金不明・統計なしなら不足を説明する。
- 不明なモデルを無料扱いせず、判明分だけの見積もりなら小計と明記する。
- 日別履歴・特定日の費用・実際の請求額・残高・為替を作らない。
- この端末のSumibiの概算で、他アプリや他端末の利用を含まず、請求や支出上限を保証しないと説明する。
- 使い方・費用の質問だけでは設定変更案を返さない。変更依頼は従来どおり適用前に確認する。

### 固定統計を使う実APIの確認例

`Tests/SettingsChatTests.swift`の固定データと同条件で、1モデルの集計期間を10日・概算費用を1 USDとする（例：GPT-6 Solの非キャッシュ入力500,000トークン、出力0）。これは評価用の架空データで、利用者の実統計に書き込まない。

| 質問 | 確認する回答 |
| --- | --- |
| 今どれくらい費用がかかっていますか？ | 現在まで約1 USD、集計期間・概算であること |
| 今後15日でどれくらい？ | 追加約1.5 USD、現在の平均ペースを継続する仮定 |
| では30日なら？ | 追加約3 USD（会話の続きの解釈） |
| 現在までを含めると？ | 累計約4 USD |
| 2倍使ったら今後1週間は？ | 追加約1.4 USD、7日・2倍の仮定 |
| 範囲だけ変換するには？ | 文字列を選択し「範囲を変換」、設定変更なし |

実機では実際の「利用状況」を根拠として同様に質問し、架空データの1 USDが回答に流用されないことも確認する。

設計時に[OpenAI公式のプロンプト構成ガイド](https://developers.openai.com/api/docs/guides/prompt-engineering#message-formatting-with-markdown-and-xml)を参照。
